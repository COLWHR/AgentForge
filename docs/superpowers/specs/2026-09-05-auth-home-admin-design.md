# 认证首页与双层管理员设计规格

## 目标

把 AgentForge 的登录、注册和管理员能力补齐到现有 React + Vite + FastAPI 架构中，并保持和当前工作台、公开广场、个人资料页兼容。

## 范围

本次只做一个统一认证与权限体系，包含：

- 首页顶部展示登录、注册入口。
- 未登录访问首页主入口、工作台、广场管理页或管理员页时，统一跳转到登录页。
- 保留现有邮箱注册、验证码校验、登录、刷新、退出、找回密码、重置密码流程。
- 新增平台管理员端和团队管理员端。
- 复用当前 Token、AuthStore、路由守卫和后端账户服务，不引入外部后台框架。

## 角色模型

### 平台级角色

- `platform_admin`：管理全局用户、团队、智能体、公开链接、插件、执行日志和系统配置。

### 团队级角色

- `owner` / `admin` / `developer`：可管理所属团队的成员、智能体、额度和团队内资源。
- `member`：普通使用者，只能访问自身可见功能。

## 前端设计

### 首页

- 首页仍然是默认入口。
- 顶部区域固定展示品牌、登录状态和操作按钮。
- 未登录状态展示 `登录` 与 `注册`。
- 已登录状态展示当前用户、进入工作台、退出登录。
- 首页主区域仍保留现有两个主入口，但未登录时点击“智能体开发”应进入登录页。

### 认证页

- 登录页、注册页、找回密码页、重置密码页继续使用现有独立路由。
- 注册页必须完整可见，不依赖隐藏入口。
- 登录完成后根据角色重定向：
  - 平台管理员进入 `/admin`
  - 其他已登录用户进入 `/develop/agents`

### 管理员端

新增 `/admin` 下的后台入口，第一版包含：

- 平台概览
- 用户管理
- 团队管理
- 智能体管理
- 公开链接管理
- 插件市场管理
- 执行日志

团队管理员端放在现有工作台体系中，固定为 `/develop/team-admin` 团队管理页入口。

## 后端设计

- 账户接口继续使用现有 `/auth/register/*`、`/auth/login`、`/auth/refresh`、`/auth/logout`、`/auth/session`。
- 用户资料响应需要带出可用于前端路由判断的角色信息。
- 后端鉴权需要区分平台管理员和团队管理员。
- 团队资源接口继续复用现有团队权限校验。
- 管理端接口优先走现有账户、团队、智能体、插件、日志相关服务，不新增独立鉴权协议。

## 路由与守卫

- `/login`、`/register`、`/forgot-password`、`/reset-password` 继续开放。
- `/develop/*`、`/profile`、`/admin/*` 必须登录后才能访问。
- `/admin/*` 还需要平台管理员权限。
- 未登录访问受保护路由时，统一跳转到 `/login`。

## 兼容策略

- 不替换当前 Zustand 认证状态管理。
- 不替换当前 API client。
- 不引入 Refine、React-admin 等外部后台框架，避免与现有工作台视觉和状态管理割裂。
- 仅在现有代码边界上补充认证入口、角色判断和管理员页面。

## 验收标准

- 首页顶部能看到登录、注册入口。
- 未登录访问工作台或管理员路由会跳转到登录页。
- 登录后能正确进入对应页面。
- 平台管理员能看到管理员端入口。
- 团队管理员能看到团队管理入口。
- 注册、登录、退出、找回密码、重置密码流程仍然可用。
- 现有前端构建通过，后端关键认证接口不回归。

## 非目标

- 本次不做第三方 SSO。
- 本次不做多租户改造。
- 本次不重构整套账户数据库结构。
- 本次不替换首页视觉语言。
